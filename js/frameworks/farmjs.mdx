Getting an application running on Fly.io is essentially working out how to package it as a deployable image. Once packaged it can be deployed to the Fly.io platform.

In this guide we'll learn how to deploy a [Farm.js](https://farmjs.dev/) application on Fly.io.

We'll be using the basic starter generated by `@farm.js/create-app`. It renders pages on the server and hydrates interactive components in the browser.

## _Deploy a Farm.js app_

We'll assume you have Node.js 22.13 or later installed and can run `npm`.

<FlyctlSnippet />

Now let's generate a new Farm.js app:

```bash
npx @farm.js/create-app@latest my-farm-app
cd my-farm-app
```

`farm build` compiles the app into a self-contained Node.js server in `.farm/.output`. Add a `Dockerfile` to the root of the app that builds it and runs that server:

```dockerfile
FROM node:22-slim AS build

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . ./
RUN npm run build

FROM node:22-slim

WORKDIR /app
COPY --from=build /app/.farm/.output ./.farm/.output

ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", ".farm/.output/server/index.mjs"]
```

And a `.dockerignore` next to it:

```
node_modules
.farm
.git
```

The runtime image only copies `.farm/.output`, which already contains the server's dependencies. If you let `fly launch` generate a Dockerfile instead, it removes development dependencies before running `npm run start`, which removes the `farm` command that `start` calls.

Now you're ready to deploy:

```bash
fly launch
```

`fly launch` uses your `Dockerfile` and sets the internal port to `3000` from its `EXPOSE` line, which is the port the Farm.js server listens on.
