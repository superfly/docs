A cache disk is local disk space attached to a single Fly Machine, for data your app can rebuild if it's lost. Think build caches, downloaded model weights, package caches, or temporary files that are too large for the Machine's root file system.

Fly.io makes a best effort to keep a cache disk's contents across Machine stops, restarts, and updates, but there's no guarantee. Your app should expect to start with an empty cache disk at any time. If you need the data back, store it on a [Fly Volume](/volumes/overview) or in [object storage](/tigris) instead.

## Cache disks, volumes, and the root file system

| | Root file system | Cache disk | Fly Volume |
| --- | --- | --- | --- |
| Survives stop and restart | No | Usually, not guaranteed | Yes |
| Survives [Machine migration](/reference/machine-migration) | No | No | Yes, the volume is forked to the new host |
| Survives Machine destroy | No | No | Yes, until you delete the volume |
| Snapshots and forks | No | No | Yes |
| Created and managed | With the Machine | In the Machine config | Separately, with `fly volumes` |
| Max size | Depends on image | 50 GiB | 500GB |

## What happens to the data

A cache disk belongs to its Machine. It's created when you create or update a Machine with a cache disk config, and it lives on the same host as the Machine.

| Event | Cache disk contents |
| --- | --- |
| Machine stops, starts, or restarts on the same host | Usually kept |
| Machine update that doesn't change the cache disk's size | Usually kept |
| Cache disk `path` changed | Kept |
| Cache disk size changed | Wiped. The disk is destroyed and a new empty one is created |
| [Machine migration](/reference/machine-migration) or recovery on another host | Wiped. A new empty disk is created on the new host |
| Machine cloned | The clone starts with an empty disk |
| Cache disk removed from the config | Disk destroyed |
| Machine destroyed | Disk destroyed |

## Performance

A cache disk has the same IOPS and bandwidth limits as a Fly Volume on the same Machine size. See [Volume limits](/volumes/overview#volume-limits) for the numbers.

## Limits

- One cache disk per Machine.
- Available in all regions.
- Maximum size is 51200 MiB (50 GiB).
- Minimum size is 16 MiB.
- The mount path must be an absolute path other than `/`, and it can't overlap `/dev`, `/proc`, `/sys`, `/.fly`, or a volume mount path on the same Machine.

## Add a cache disk in fly.toml

Add a `[[cache_disk]]` section to your app's `fly.toml`, then run `fly deploy`:

```toml
[[cache_disk]]
  size = "1gb"
  path = "/cache"
```

- `size`: the disk size, with a unit, such as `512mb` or `1gb`.
- `path`: where to mount the disk in the Machine.
- `processes`: optional. The [process groups](/launch/processes) that get the cache disk. Without it, only Machines in the default process group get one.

Each Machine can have only one cache disk, so a process group can match only one `[[cache_disk]]` entry. To remove the cache disk, delete the section and deploy again.

## Add a cache disk with flyctl

Use `--cache-disk-size` and `--cache-disk-path` with [`fly machine run`](/flyctl/cmd/fly_machine_run), [`fly machine create`](/flyctl/cmd/fly_machine_create), or [`fly machine update`](/flyctl/cmd/fly_machine_update):

```bash
fly machine update <machine-id> --cache-disk-size 1gb --cache-disk-path /cache
```

To resize an existing cache disk, pass only `--cache-disk-size`. To remove it, set `--cache-disk-size 0`.

## Add a cache disk with the Machines API

Set `cache_disk` in the Machine config when you [create](/machines/api/machines-resource#create-a-machine) or [update](/machines/api/machines-resource#update-a-machine) a Machine:

- `size_mb`: the disk size in MiB.
- `path`: where to mount the disk in the Machine. The disk is formatted as ext4 and mounted at this path.

```bash
curl -i -X POST \
  -H "Authorization: Bearer ${FLY_API_TOKEN}" -H "Content-Type: application/json" \
  "${FLY_API_HOSTNAME}/v1/apps/my-app-name/machines" \
  -d '{
    "config": {
      "image": "registry-1.docker.io/library/ubuntu:latest",
      "guest": {
        "cpu_kind": "shared",
        "cpus": 1,
        "memory_mb": 256
      },
      "cache_disk": {
        "size_mb": 1024,
        "path": "/cache"
      }
    }
  }'
```

This creates a Machine with a 1 GiB cache disk mounted at `/cache`.

To resize the disk, update the Machine with a new `size_mb`. The old disk and its contents are discarded. To remove the disk, update the Machine config without `cache_disk`.

See the [`fly.MachineCacheDrive`](/api/machines/models#fly-machinecachedrive) reference for the full schema.
